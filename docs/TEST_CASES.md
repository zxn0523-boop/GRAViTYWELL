# MVP 测试案例

目标不是检查回答是否“像聊天”，而是检查地点真实、路线完整、公平差异清楚、错误不被掩盖。

| # | 场景 | 主要检查点 |
|---:|---|---|
| 1 | 五角场、虹桥站，公共交通，咖啡馆 | 同城两人基础链路 |
| 2 | 静安寺、徐家汇，驾车，晚餐 | 驾车路线与距离 |
| 3 | 五角场、苏州园区，公共交通 | 邻城路线与超时警告 |
| 4 | 杭州东站、绍兴北站，公共交通，看展 | 第二组邻城组合 |
| 5 | 三人从人民广场、张江、虹桥出发 | 三人公平差值 |
| 6 | 四人、四个不同地铁站 | 4 人上限与路线矩阵 |
| 7 | 一人驾车、一人公共交通 | 混合交通方式 |
| 8 | 只说“我们周末见面” | 逐项补问，不猜地址 |
| 9 | 只提供一名参与者 | 要求至少两人 |
| 10 | 提供五名参与者 | 提示 MVP 最多四人 |
| 11 | 地址写“园区” | 暧昧地址必须确认 |
| 12 | 地址写不存在的建筑名 | 明确报告无法解析 |
| 13 | 时间写“本周六下午” | 相对时间转 ISO，并按固定规则补为 14:00，不再追问几点 |
| 14 | 约会在两个月后 | 不伪造远期天气 |
| 15 | 雨天要求户外散步 | 天气适配降分或警告 |
| 16 | 用户说“更安静一点” | 保留地址，只更新偏好并重算 |
| 17 | 用户说“照顾小张” | 增加靠近小张的搜索种子，评分显示“照顾偏向”，小张耗时应下降 |
| 18 | 用户说“第二个太远” | 能读取上一轮候选上下文 |
| 19 | 所有候选均超过 90 分钟 | 返回带警告的相对最优备选 |
| 20 | 某候选任一人无路线 | 淘汰该候选，不补造路线 |
| 21 | 高德超时或额度不足 | 返回清楚错误，不让 LLM 猜答案 |
| 22 | DeepSeek 首次返回空 JSON | 同一轮自动重试，成功后继续；连续三次失败才提示直接重发，无需重启会话 |
| 23 | 点击“采纳” | 会话、地址和候选立即删除 |
| 24 | 点击“重新开始”或超过 24 小时 | 会话清空，下一轮不继承旧信息 |
| 25 | 明确要咖啡馆并要求“设计感” | 氛围细化咖啡馆，不得替换成纯艺术馆 |
| 26 | 散步、夜景或城市漫游 | 候选扩展到公园、绿道、街区和广场 |
| 27 | 到达时已闭店或一小时内闭店 | 有明确营业时间的地点必须淘汰 |
| 28 | 两个路线相同但地图评分不同 | 高评分地点应获得更高地图口碑分 |
| 29 | 两人出发地不同，但要求“在国贸附近” | 先确认北京国贸，只搜索其 5 公里内地点，位置要求优先于交通公平 |
| 30 | 没有提出目标区域 | 继续使用默认 balanced 权重，交通公平优先 |

同一套输入应重复执行至少三次，地图结果可随服务更新，但公平排序使用的路线数字必须能够解释。
